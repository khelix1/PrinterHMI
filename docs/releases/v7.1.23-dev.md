# PrinterHMI v7.1.23-dev

Speed up preparation before starting live print progress. Volume cancellation
checks previously paused for one scheduler tick on every call, including probes
inside sampling, flood fill, mesh extraction and smoothing. They now check request,
profile, network exclusivity and deadline on every call, while yielding at a
20 ms wall-time interval. Checks run again after each yield so cancellation arriving
while asleep is observed immediately. The 120-second preparation deadline remains.

If all source paths are retained in RAM (stride 1, retained count equals generated
count, at most 32,768 paths), copy them into an optional worker-owned snapshot.
Refinement can then avoid rereading SD or downloading/parsing the file again.
The copy uses at most 1,310,720 bytes and remains valid after UI close/retirement.
Copy allocation failure, reduced samples and larger retained sets keep the existing
SD or fingerprint-checked HTTP path. Every exit and task-start failure frees the
copy. This is session reuse of parsed data; persistent file caching is not added.

The triangle raster also rejects faces wholly outside the canvas before setting
up scanlines. It especially avoids walking offscreen X spans during close zoom.
Resolution, triangle limits, smoothing and camera behavior are unchanged.

With the supplied 1,780-path clip and host-emulated 1 ms sleeps, preparation changed
from 2,299 ms / 1,567 sleeps / one replay GET to 738 ms / 34 sleeps / zero replay
GETs. Its 61,064 triangles and geometry hash remained identical. In a 120-view host
raster comparison, 1x/4x/16x changed from 3.52/6.02/6.68 to 3.04/5.26/4.65 ms per
frame, with identical pixel hashes at each zoom. These are host observations, not
tablet timings or a promised speedup; real network and SD times were not measured.

Host ownership, cancellation, OOM, HTTP fallback/integrity, raster guards and native
UI audits pass. Build/flash and compare the same file on the tablet using
`./tools/build_idf6_hosted3.sh`; image: `build-idf6-hosted3/PrinterHMI.bin`.
Live following remains deferred. The Dashboard filename improvements are included.

The accompanying bug/security pass fences profile changes during endpoint/key
capture and uses non-optimizable key erasure, including refinement task-start
failure. Tests inspect freed job storage for an API-key marker and simulate a
profile change in the capture sequence. See `docs/GCODE_VIEWER_REVIEW.md` for scope,
fixed findings, evidence and remaining target validation.
