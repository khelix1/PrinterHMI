# PrinterHMI v7.1.28-dev

The new tablet timing block isolates a moving Up to frame: body 40.2 ms,
material 94.3 ms, travel 0 ms, total 443.7 ms (9 movement samples completed).
About 309.2 ms is outside the measured geometry stages; this includes publish,
render-handler gaps, other UI/task work and instrumentation/clear overhead.
It is not all attributable to display or sleep. Material is the larger drawing
stage. The existing renderer yields after roughly 8 ms, and the LVGL port also
delays one FreeRTOS tick after handler runs, so many short slices can accumulate
handoff costs. The port and system-wide display/touch settings are unchanged.

Moving Up to and Single now use a 20 ms work budget instead of 8 ms, with a
32-quantum hard iteration cap instead of 8. Checks remain between each quantum:
64 material paths or 2048 body/travel work items. A callback may exceed the time
budget by one quantum and publishing; it does not render an arbitrary whole frame
synchronously. Input/camera changes coalesce between slices and only complete
frames publish. All, settled sections and no-mesh fallbacks retain their prior
8 ms budgets. Target input latency and task fairness still need verification.

During selected-layer movement, beads use a closed rectangular cross-section:
8 vertices / 12 triangles instead of 16 vertices / 28 triangles. All source paths,
width/height, source top Z, endpoint overlap, minimum visible thickness, depth
and gold planar shading remain. These are solid faces, not Lines, and no path
sampling or synthetic cap fills the interior. Bevel details change while moving;
the existing full-resolution, eight-sided beads and exact shell contact band
return after release. The body still follows the previous optional gesture mesh.
No persistent geometry or per-frame heap allocation is added.

Tests cover all 1500 isolated source paths in a dense layer, real top Z, open
spaces between paths, gold pixels, depth occlusion, travel/layer filtering,
incremental equivalence and raster canaries under ASan/UBSan. A 48-view host
material test measured 3.57 ms/frame detailed versus 1.91 ms/frame gesture; this
is synthetic host evidence, not tablet FPS. The frozen v26 material and section
references still verify exact settled output. Native UI tests show fewer render
handoffs under a simulated fixed call cost, bounded multi-slice rendering with
no partial publication, preserved movement diagnostics, and the complete five-theme
mode/travel/camera/input/memory-fallback matrix.

Details now includes movement slice count, publish time and other elapsed time,
so the next target result can separate drawing improvements from handoff costs.
Use `./tools/build_idf6_hosted3.sh`. Check continuous Up to and Single orbit/pinch,
then lift to verify detailed material and selected cut restoration. Colors and
live following remain paused until movement is acceptable.
