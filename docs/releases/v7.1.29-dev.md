# PrinterHMI v7.1.29-dev

Files row thumbnails previously used full shared 286×215 canvases for wells of
at most 76 pixels and always selected the largest metadata thumbnail. Each row
now uses a 96×96 packed aspect-preserving canvas and prefers the smallest source
whose long edge reaches 96 pixels. The largest available source remains a fallback,
including files that only contain a high-resolution thumbnail. No slicer changes
are needed. Large-only PNGs still have download/decode costs; destination sampling
and permanent row storage are reduced.

The row pool and queue now match the browser's 64-file bound instead of 24 slots
and 12 queued jobs. This avoids abandoned later-row requests while retaining a
smaller pixel pool: 1,179,648 bytes maximum versus 2,951,520 previously. Each slot
uses at most 18,432 bytes versus 122,980. Existing SD PNGs remain reusable, while
new row sources use a separate `.png.row.png` namespace and never overwrite full
preview cache files. Tapping an icon still shows its owned fallback followed by
the existing asynchronous high-resolution lightbox. Other preview sizes and the
3D viewer's movement improvements are retained.

Real cJSON/LVGL tests pass for smallest adequate source, missing/invalid dimensions,
portrait and large-only fallback, malformed metadata, cold/warm SD and no-SD fetches,
metadata/download failure cleanup, variable row dimensions, ownership transfer,
stale publication and bounded storage. Fullscreen worker success/retry/stale
results and tap/lifetime checks pass across five themes/densities/text sizes.
The full ESP-IDF build and on-device loading times remain to verify.

Build with `./tools/build_idf6_hosted3.sh`. Check the first screenful, scroll beyond
24 files if available, and tap an icon to verify the original high-resolution
preview still loads. Colors remain the next feature batch after reported issues.
