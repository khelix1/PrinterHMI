# PrinterHMI v7.1.31-dev

Files loading follow-up after the first cleanup batch. The list loader discarded
decoded row readiness on every successful refresh, and compressed SD PNG caches
still required full decoding. A parsed file catalogue now preserves unchanged
ready rows in RAM. A small decoded RGB565 SD cache avoids PNG fetching/decoding
on later visits and after restarts. The existing 96×96 capacity, aspect fit and
original-resolution lightbox remain.

RAM reuse requires matching endpoint, profile generation, credentials, path,
size and modified time. Disk identity includes endpoint/path/size/modified;
missing or invalid revisions skip reuse. A fixed 256-bucket namespace bounds
live decoded data to about 4.8 MB. Full keys, dimensions, exact length and checksums
are validated before publication. Changed files, damaged cache records and
collisions fall back to fresh metadata/PNG. Old unversioned row/full PNG caches
are no longer sources for the row worker, avoiding stale overwritten-file images.
Other preview owners and the v30 cleanup remain intact.

Host checks pass for RAM reuse without allocation, queue or HTTP; the actual
worker's decoded-SD hit; changed-file invalidation; credential/profile fences;
profile change during fetch; all 64 queued entries; and fullscreen ownership,
worker and theme/text-size behavior. ASan/UBSan storage checks cover identity,
collisions, checksum/size/truncation/trailing guards, and write/close/FatFS rename
failures. File-list worker and existing thumbnail storage/component audits pass.

Build with `./tools/build_idf6_hosted3.sh`. Let the first Files visit finish, leave
and reopen it, then repeat after a restart with SD present. New files still need
one initial PNG load. Overwriting a file should rebuild its thumbnail. Target
speed and full ESP-IDF validation remain pending.
