# v7.1.37-dev — connection-state publication race

The operator reported OFFLINE → ONLINE → OFFLINE → ONLINE when selecting a
printing printer, persisting despite v36's preview fixes. A separate race exists
in runtime connection handling: after a stale WebSocket probe, a status callback
can publish online state before the runtime unconditionally writes offline.
The new deterministic host regression reproduces this with the previous runtime.
This identifies an avoidable writer race; it does not prove that every observed
transport reconnect on hardware is caused by it.

Verified status timestamps now publish under Moonraker's existing state lock.
The runtime's stale branch calls a bounded expiry helper that checks the latest
timestamp under that same lock. An intervening valid status publication is kept,
including equal-value frames. Runtime connection flags come from the resulting
snapshot. The fresh fast path also uses snapshot truth, rather than assuming
online after an earlier successful probe. The old misleading HTTP-bootstrap log
is renamed when waiting for fresh status.

The existing three-second limit, actual disconnect/closed events, profile reset,
Klipper shutdown/readiness rules and no-competing-HTTP reconnect policy remain.
This is not a display debounce or a longer stale-data grace period. Existing
preview continuity, cache ownership and all prior cleanup remain.

## Validation and target gate

`connection_refresh_race_test.py` compiles the actual JSON/status merge, reset,
expiry and runtime tasklet with the real cJSON implementation under ASan/UBSan.
It injects an update after a stale probe and immediately before the expiry lock,
checks equal-value renewal, exact expiry boundary, genuine disconnect, profile
reset, shutdown/disconnect notifications, invalid clock and HTTP ownership.
Peripheral catalog merges and SDK calls are mocked. LeakSanitizer is disabled
in this host environment. The v36 runtime fails the race reproducer.

Existing offline-navigation/rebind, readiness, profile-switch, security,
Dashboard/offline/camera, Active Print and chooser checks also run. Host passing
is not a full firmware build or hardware timing measurement. Build with
`./tools/build_idf6_hosted3.sh` and repeat idle/printing/paused profile switching,
also checking that a genuinely unavailable destination becomes offline.

Apply incrementally over v7.1.36-dev on `chore/stale-code-cleanup-main`. The guarded
updater supports backups/rollback/recovery and does not commit, push, merge,
build, flash or send printer commands.
