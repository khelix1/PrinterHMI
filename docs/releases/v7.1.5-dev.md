# PrinterHMI v7.1.5-dev

Fix the reported `G3: Segment limit at arc` failure on `feature/gcode-viewer-3d`.
A full main sample buffer now compacts progressively and continues parsing.
Samples remain independent: discarded endpoints are never joined into fabricated
lines. One extrusion segment from every retained Z level, one from each tool,
and the final path are retained separately. Bounds and layer/tool metadata are
computed across generated input, not just the initial sample buffer.

The viewer labels sampling/coarser arcs as REDUCED DETAIL, or adds the detail
ratio to an existing PARTIAL notice. Details reports generated paths, retained
samples, stride, layer anchors and arc reduction. Gaps can appear, especially
when inspecting a single layer; this is an approximation, not full-detail storage.
Other actual limits and unsupported input still produce PARTIAL with a reason.

Streaming budgets are 64 MiB and 60 seconds. Loading shows consumed KiB, generated
paths and layers. Progress is request-fenced and UI-owned. Existing cancellation,
TLS, redirect and printer ownership rules remain intact. Geometry storage is
about 1.1 MiB plus the existing canvas. No printer commands are sent.

Host regression reproduces 32,759 paths plus an arc needing more than nine slots,
then continues through 901 layers. Additional cases cover sparse late features,
travel ownership after compaction, per-layer raster anchors and memory guards.
Target performance and the user's original file still need a tablet check.

Build: `./tools/build_idf6_hosted3.sh`. OTA:
`build-idf6-hosted3/PrinterHMI.bin`.
