# PrinterHMI v7.1.8-dev

First compact-surface/SD-detail experiment toward high-resolution preview detail,
with all processing on the tablet.

Solid/All and Solid/Up to can merge collinear runs and matching runs on adjacent
levels into shaded wall panels. The bounded builder uses a nominal 0.45 mm width
and 0.20 mm initial base thickness. It does not invent skins/infill or reconstruct
CAD. Irregular contours may compress poorly; non-planar motion or panel-budget
exhaustion falls back to paths with explicit diagnostics.

A mounted SD card caches generated geometry under PrinterHMI/gcode-preview.
Single-layer inspection reads its complete available range without HTTP, with
background loading and cancellation. It preserves transition travel ownership,
checks records before use, and keeps worker references through viewer dismissal.
Cache files are session-scoped and removed when no longer owned; interrupted
session leftovers are cleaned on the next successful cache opening. The cache
is bounded to 128 MiB; layer RAM is bounded to 262,144 paths with explicit sampling
above capacity. Existing parse/arc limits still apply. No SD means path fallback.

The synthetic 400,000-extrusion test produces four panels and retains every late
layer path on SD. This is a favorable test, not a general compression ratio.
ASan/UBSan and five-theme LVGL tests cover the new pipeline and lifetimes.
Target SD/load/render performance and fidelity against high-resolution previews
remain tablet checks.

Build: `./tools/build_idf6_hosted3.sh`; OTA:
`build-idf6-hosted3/PrinterHMI.bin`.
