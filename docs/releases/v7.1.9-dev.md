# PrinterHMI v7.1.9-dev

First end-to-end standalone STL-to-tablet solid model preview experiment.
PrusaSlicer remains unchanged. A Python standard-library converter accepts
binary/ASCII STL and writes a compact, checked PHM mesh. Optional grid clustering
fits a chosen triangle budget; --no-simplify refuses that reduction. Source STL
and G-code are never changed.

Tools > 3D G-code Viewer > Mesh opens an SD model chooser. A separate model
viewport provides smooth shaded/edge rendering, orbit, Bed Mesh style pinch,
Top/Front/3D, Reset and Details. It is standalone model geometry, not automatically
associated with G-code, generated supports/infill or live print progress.
Closing returns to the toolpath viewer. Parent detail work/rendering pauses;
parent dismissal or printer switching also closes the mesh view.

File counts, lengths, CRCs, coordinates, normals and indices are validated before
adoption. Local SD reads are request/profile fenced with bounded allocation and
cancellation. Drawing proceeds in batches; gestures use sampled wireframes and
restore full mesh detail on release. The included fluted-ring demo has 6,144
triangles, 3,201 vertices and a 75,356-byte file.

Host ASan/UBSan and five-theme real LVGL tests cover conversion, validation,
rendering, gestures, modal ownership, allocation failures and cleanup. Target
build/SD/frame-time/appearance checks remain pending. Conversion is a display
approximation, not topology-preserving CAD simplification.

Build with `./tools/build_idf6_hosted3.sh`. OTA image:
`build-idf6-hosted3/PrinterHMI.bin`. Copy tools/mesh-preview/demo.phm into the SD
card's /PrinterHMI/meshes/ directory. See tools/mesh-preview/README.md.
