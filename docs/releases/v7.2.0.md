# PrinterHMI v7.2.0

## Case lighting

Tools now includes Lighting when `output_pin case_led` is detected for the active
printer. The existing four Tools tiles keep their arrangement. Printers without
that output do not show the action, and late discovery updates it while Tools is
open.

- On/off toggle and live PWM brightness from 0–100%. Digital outputs offer
  on/off only; existing PWM scale settings such as 1, 100 or 255 are honored.
- Brightness sends once when the slider is released. The requested position stays
  visible while Applying is shown, then live status confirms it. Failures or
  missing confirmation show local feedback; commands are never retried automatically.
- External client/macro changes update the dialog. Turning on restores the last
  nonzero level observed while the dialog is open, or 100% when none was observed.
- Lighting remains usable during printing and pause. Offline, unknown or changed-
  printer states block commands. Discovery/configuration/readings reset on
  reconnect and Klipper restart. Navigation and popup deletion retire UI timers.
- Use the current authenticated/TLS Moonraker WebSocket, without extra network
  polling, HTTP fallback, new persisted settings or printer-side macros.

## Review fixes

A nonzero level below 1% now remains visibly On (shown as <1%), and Off still
sends a real zero-value command. Tightened live confirmation matching prevents a
nearby old reading from confirming a requested change. Floating-point command
formatting happens outside the RTOS lock, with a revision check before publishing
a pending request. Configuration/reset or competing commands during formatting
invalidate the old request. Retire the UI action epoch when a dialog closes, so
an in-flight callback cannot overwrite a replacement dialog’s feedback.

Remove unused camera/queue/task test stubs and redundant test sources from the
lighting host harness. No unused lighting production entry points were found.
Firmware source inventory remains 159. Configuration and backup migrations,
Quiet connection-loss warnings and existing printer controls remain unchanged.

## Requirements and scope

The light must already work as `[output_pin case_led]` in Klipper. PrinterHMI does
not change its pin, inversion, PWM, shutdown or other configuration. RGB chains,
`fan_generic`, `pwm_tool` and other output names are outside this release.
The experimental G-code viewer and Linux Theme Maker remain parked. The existing
3D Bed Mesh workspace remains available.

## Validation and limitations

Host checks cover the actual model and nonblocking transport adapter, normalized/
scaled PWM and digital output, malformed data, old responses, timeout/retry,
formatting outside locks, reset/configuration revision changes and competing
commands. Native LVGL checks cover layouts/teardown, slider feedback, sub-1% Off,
active-printer visibility and all five themes/densities/text sizes. The dim-light
regressions reproduce on unchanged v7.2.2-dev. Model/adapter/lock fixtures use
ASan/UBSan; this sandbox disables LeakSanitizer. Host fixtures do not simulate
RTOS concurrency, physical outputs or a new long-print soak result.

Development panel feedback accepted on/off, slider presentation and detection
through v7.2.2-dev. Final version firmware and the review fixes still require a
panel smoke check. Stable publication rebuilds the complete P4+C6 stack and audits
firmware size, compiler warnings, dependency locks and packaged checksums.
Supported hardware/toolchain remain JC1060P470C-I/W, ESP-IDF 6.0.2, LVGL 9.5.0 and
ESP-Hosted 3.0.5. See [Lighting](https://github.com/khelix1/PrinterHMI/blob/v7.2.0/docs/LIGHTING.md),
[Known issues](https://github.com/khelix1/PrinterHMI/blob/v7.2.0/docs/KNOWN_ISSUES.md)
and [Security review](https://github.com/khelix1/PrinterHMI/blob/v7.2.0/docs/SECURITY_REVIEW.md).
