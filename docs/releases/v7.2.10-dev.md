# v7.2.10-dev

Confirmed demo print starts now highlight Dashboard when returning there.
The Dashboard destination owns its selected navigation state, so it also works
for programmatic navigation. The normal firmware start-completion bridge now
returns to the same Dashboard destination only after a successful start. Failed
or cancelled requests remain in Files.

Demo advertises object exclusion and publishes two sample objects, their bed
polygons, current-object state and per-printer exclusions through the locked
Moonraker snapshot. Object controls are available while printing on Dashboard
and Printer. Excluding both objects disables further exclusion. A fresh file or
printing/paused/idle scenario resets exclusions; switching printers preserves
each sample printer's current state.

Host checks exercise the actual normal-start bridge, Dashboard route and object
publisher with stubs instead of a printer. Native pixel tests cover the selected
navigation state after successful/cancelled confirmation in Studio and Operator.
The real object dialogs and isolation harness are also checked. Hardware build
and touch verification still use `./tools/build_idf6_hosted3.sh`.
