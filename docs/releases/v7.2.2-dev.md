# v7.2.2-dev — Show Lighting only for detected lights

The Tools header Lighting action starts hidden. The existing Tools refresh makes
it visible only after discovery reports output_pin case_led for the current
printer generation. Missing, undiscovered, reset/reconnecting or stale-generation
lighting snapshots keep it hidden. Detection arriving while Tools is already open
reveals it without rebuilding the page or moving its four tiles.

Recheck detection and generation on click as well as refresh, so a formerly
visible button cannot open Lighting for a different printer before the next timer
tick. Known detection for the same printer may remain visible while offline;
the dialog still blocks commands until its live connection/configuration/value
are ready. No network polling, command or configuration behavior changes.

Native Tools tests cover undiscovered/missing/present lights, printer switching
before refresh, discovery arrival/removal/reset and action routing across all five
themes, densities, text sizes, widths and custom metric profiles. Retain the
Lighting UI/model/transport and updater recovery checks. Source count remains 159.
