# v7.2.4-dev — project input and security hardening

Date: 2026-10-30. Development patch based on main `681c7eb4205a`.

The camera connection test now checks its 256 KiB JPEG frame capacity for every
byte copied, rather than only between network reads. This fixes a reproduced
heap overwrite. It also bounds the frame-read phase to five seconds plus an
in-flight read timeout, rejects HTTP/header failures, and refuses oversized URLs
instead of silently testing a truncated endpoint. Normal, maximum-size and
single-byte fragmented JPEG inputs remain accepted.

WebSocket assembly now accepts only contiguous bytes of one bounded message,
rejecting orphan/gapped/overlapping/changed-length/generation fragments before
JSON parsing. Reconnect/close/client retirement clears partial assembly state.
This is defensive SDK-event boundary validation; code execution or data leakage
through this path has not been demonstrated.

Bed Mesh rejects non-finite heights and values outside its float-display safety
range before changing the cached mesh. Invalid coordinate updates cannot poison
previous valid coordinates. Partial notifications and explicit clears retain
existing semantics.

Application OTA logs no longer include complete saved/download URLs, which may
contain credentials or tokens. The stored and requested URL itself is unchanged.
The unused synchronous profile-health poller and its public declaration are
removed; the combined worker remains the health owner. About and connection
control test fixtures are brought up to date without changing those UI flows.

The existing 90-suite host run passed 88 suites initially. Its two failures were
stale About assertions and missing mesh-owner stubs; both are repaired and pass.
Three additional sanitizer-backed suites cover camera input, WebSocket fragments
and Bed Mesh JSON. LeakSanitizer is disabled in this host environment. Target
build, OTA, live camera, reconnect, multi-printer, Bed Mesh and soak validation
remain pending. Firmware sources remain 159.

Repository documentation is reviewed in the same batch: current security,
build/flash/release, defaults, cache paths and OTA channel guidance are corrected;
checkpoint-specific engineering records are explicitly historical. Published
release history and license notices are retained.

This is not a security certification. See
[the audit and remaining trust boundaries](https://github.com/khelix1/PrinterHMI/blob/main/docs/PROJECT_AUDIT_2026_10_30.md).
No signing, eFuse, transport-policy or device-encryption changes are part of this
patch. Build with `./tools/build_idf6_hosted3.sh` on `fix/project-audit`.
