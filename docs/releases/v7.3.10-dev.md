# v7.3.10-dev

Live device and lighting boundary hardening in one batch.

Device status formatting keeps the catalog generation captured at merge start and rejects publication into a replacement catalog. This prevents old readings from reaching a newly selected printer with the same object names. Device numeric formatting and driver fault flags reject non-finite values.

Endstop response IDs must be finite integers in the reserved range before conversion, so a fractional ID cannot masquerade as the pending request. Existing request, owner and timeout checks remain in force.

Console and Lighting now share complete-document JSON parsing in `json_document_parse.h`, reusing the existing nesting/size preflight. Lighting rejects trailing data, embedded NUL and excessive input rather than accepting a valid prefix as confirmation of a pending change. A released-source regression reproduces the false confirmation with trailing data.

Host tests compile the actual controllers with AddressSanitizer, UndefinedBehaviorSanitizer and float-cast-overflow instrumentation. A lock-boundary callback replaces the device catalog during a merge; the new catalog stays free of the old reading. Endstop tests cover malformed IDs, stale generations, late responses and timeouts. Existing Lighting transport/lock tests, Console frame tests, UI checks and demo isolation are checked separately. These are deterministic host interleavings, not a complete multithreaded race proof.

Build with `./tools/build_idf6_hosted3.sh`. On hardware check Lighting on/off and brightness, Devices readings, Tools motion/endstops, and printer switching while these pages are open.
