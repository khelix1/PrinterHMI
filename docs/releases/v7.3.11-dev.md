# v7.3.11-dev

File request bounds and parser cleanup.

Supported filenames now have sufficient space through metadata URL encoding, HTTP URL construction and JSON escaping for print-start requests. Inactive-printer preview encoding uses its filename buffer size. Thumbnail HTTP paths also accommodate the existing row-preview encoder capacity. Print-start rejects filenames beyond the existing 159-byte limit before client creation.

The file parser uses bounded, complete JSON documents, skips malformed individual entries, and omits overlong paths instead of creating selectable truncated aliases. Numeric file statistics reject non-finite or negative values. Invalid responses produce local retry feedback. The old text-scraping fallback, callback and public interface are removed. Existing 16 KiB list-buffer and 159-byte filename limits remain.

Metadata formatting bounds floating-point values before integer conversions; invalid/extreme ETA displays as unavailable and other invalid numeric quantities use zero. Host instrumentation reproduces the released formatter's infinity-to-int conversion and the released request path's rejection of an otherwise supported encoded filename.

Tests use the actual file parser/formatter, extracted production HTTP request functions, real cJSON and typed SDK fixtures under AddressSanitizer, UndefinedBehaviorSanitizer and float-cast-overflow checks. Worker/UI, security-boundary and demo regressions are checked separately. Build with `./tools/build_idf6_hosted3.sh`; on the tablet verify file browsing, refresh/search/folders, long/non-ASCII names, details/thumbnails and print confirmation.
