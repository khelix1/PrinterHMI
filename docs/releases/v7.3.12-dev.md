# v7.3.12-dev

Folder thumbnail resolution. Moonraker metadata returns thumbnail `relative_path` relative to the G-code parent folder. PrinterHMI previously used it directly as a root-relative path, so nested files could request the wrong PNG URL.

The shared stateless resolver converts `folder/sub/part.gcode` plus `.thumbs/part.png` into `folder/sub/.thumbs/part.png`, then the existing encoder handles the full result. Files rows, details/selected previews, fullscreen previews and inactive-printer previews all use this rule. Root-level files keep their existing paths. Absolute/traversing and over-capacity paths are rejected without truncation. Selected-preview encoding has space for the resolved path.

Metadata requests already retain the full G-code path. The real details formatter regression verifies nested metadata, ETA and thumbnail resolution together; the row fetch regression checks the actual requested thumbnail path. Host checks cover root/nested folders, spaces, Unicode, percent/hash characters, in-place use and boundaries under sanitizers. Preview ownership/UI, detail worker and demo regressions are checked separately.

Reference: [Moonraker file management](https://moonraker.readthedocs.io/en/latest/external_api/file_manager/).

Build with `./tools/build_idf6_hosted3.sh`. On the tablet open a nested G-code file, verify row/details/fullscreen previews and metadata, then check root files and active/inactive printer previews.
