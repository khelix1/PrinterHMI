# v7.3.14-dev

Command preservation across action resolution and transport fallback. The macro builder and action resolver now share their 640-byte capacity (639 command bytes plus NUL). The resolver rejects oversized requests and clears its output, instead of silently shortening the command.

HTTP script bodies and the permanent WebSocket request buffer now reserve enough room for every supported command byte to expand during JSON escaping, plus the larger JSON-RPC envelope. Previously HTTP could reject even an unescaped 639-byte command, and WebSocket could reject an escape-heavy command. Unsupported control characters still fail; emergency-stop and firmware-restart routing retain their dedicated endpoints.

The command limits belong in the stateless `printer_command_limits.h` header. The macro editor and resolver use that shared capacity; the Console keeps its existing 256-character editor limit. No command is split or retried as fragments.

Host verification exercises actual macro construction, resolution and both transport adapters. Regression cases include a complete 639-byte parameterized macro, oversized action rejection, aliases and confirmation categories, maximum-length quote/backslash escaping, emergency routing, authentication/TLS, network arbitration and transport failures. Both original defects were reproduced against the checkpoint source. The resolver test runs with AddressSanitizer and UndefinedBehaviorSanitizer.

Build with `./tools/build_idf6_hosted3.sh`. On the tablet check ordinary Tools actions, macro parameters and Console commands. Target compilation and memory validation remain local; the HTTP request buffer grows by 766 stack bytes and the permanent WebSocket buffer by 382 bytes.
