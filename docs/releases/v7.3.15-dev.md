# v7.3.15-dev

Saved TLS certificate recovery. The CA trust store no longer marks a profile loaded before NVS succeeds. A temporary storage open/read failure remains retryable, allowing secure reconnection when storage recovers instead of requiring a reboot. Missing namespace/key results remain cached as absent; importing a certificate replaces that cached state.

Stored strings must have a valid returned length, exactly one terminating NUL at the end of that length, and the same bounded PEM certificate markers required by imports. Failed or malformed reads clear the candidate buffer and do not publish it. The store retains per-profile PSRAM-first ownership and internal-RAM fallback. File import/write failures preserve the currently loaded certificate. Full X.509 validation remains in the TLS stack; these checks do not establish certificate authenticity.

Actual trust-store and transport-policy host tests run under ASan/UBSan with storage-open/read failures, allocation recovery, missing storage, malformed strings, profile isolation, failed writes/imports, embedded NUL files, and exact 4095-byte/oversized file boundaries. HTTPS and WSS fail closed during the storage error and recover with the configured CA; HTTP plaintext fallback is not permitted. The previous sticky read failure reproduces against the checkpoint implementation. Existing security boundary tests also pass.

Build with `./tools/build_idf6_hosted3.sh`. If you use a TLS printer profile, check reconnection after reboot and profile switching; otherwise check ordinary printer switching and connection behavior. Target firmware compilation and tablet validation remain local.
