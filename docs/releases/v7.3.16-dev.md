# v7.3.16-dev

Moonraker WebSocket discovery no longer clears existing controls or configuration when an object-list or config reply is missing its expected data. Discovery IDs must match exactly; command replies require an integer ID in the supported range.

Response routing shares one parsed object across response handlers. The response router and status merger both require complete JSON objects within the existing receive capacity and a nesting limit of 16. Trailing data, embedded NUL bytes, and oversized documents are rejected.

Host tests exercise the real response handlers using cJSON, including malformed replies after a valid discovery and valid command errors. Firmware and tablet validation remain local.
