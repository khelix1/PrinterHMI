# v7.3.49-dev

Saving a configured profile with unchanged normalized connection fields now
succeeds without rewriting flash or advancing configuration generation.
Saving the same primary camera URL is likewise a no-op.

The profile editor invokes its active-connection change callback and displays
Reconnecting only when a configuration generation actually changed. Accepted
connection changes still trigger the callback if a later camera/security save
fails, so the runtime follows the settings that were already accepted.

Host storage regressions cover no-op persistence and changed/failing saves;
profile editor tests cover no-op completion and existing failure/replacement
behavior. Build and tablet verification remain local steps.
