# v7.3.50-dev

Inactive printer status and metadata requests now use that profile's captured
API key, including an empty key when none is configured. The worker no longer
retains the active printer's startup key for unrelated endpoints.

Requests capture their profile settings and discard results if the host, port,
API key, transport mode, configured state or active selection changes before
publication. Metadata/thumbnail stages repeat the ownership check. The captured
key is cleared when the polling call returns.

The health cache hides observations whose endpoint no longer matches the current
profile. Each polling turn reconciles inactive edits even when active connection
generation is unchanged; unknown endpoint health is not delayed by the previous
endpoint's retry timestamp. Authoritative demo publishers remember their endpoint.

Host regressions cover distinct/empty credentials, five in-flight inactive edits,
generation changes, retry/backoff and health reconciliation. Build and tablet
verification remain local steps.
