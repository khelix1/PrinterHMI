# v7.3.52-dev — Setup Wi-Fi scan recovery

Setup Wi-Fi scanning now uses the shared atomic worker/result slot rather than
separate volatile done/busy flags. Records are published with release/acquire
ordering, and a completing worker makes no later busy-state write that could
clobber a new scan. Repeated Scan taps reuse the current worker; reopening after
a closed scan starts a fresh request.

A failed scan or AP-count/record read now reports a scan failure with a retry
prompt. A successful empty scan still reports no networks. Task creation failure
releases ownership so another attempt can start. Demo results use the same slot.

Validation: host Setup layout/ownership suite across themes, density, text and
viewport settings, including failure/retry, empty results, immediate completion,
and close/reopen; standalone production owner compilation with warnings as
errors. ESP-IDF build and tablet verification remain local.
