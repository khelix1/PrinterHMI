# v7.3.53-dev — Preserve calibration homing through macro resolution

Calibration dialogs can request `G28` followed by a standard calibration command
when XYZ is not homed. The semantic resolver previously replaced that whole script
with a detected printer macro, dropping the explicit homing prerequisite even
though the dialog promised to home first.

The resolver now retains `G28` before the selected macro. For example,
`G28\nQUAD_GANTRY_LEVEL` with a detected `QGL` macro becomes `G28\nQGL`.
Unprefixed actions still send the macro alone. Literal parameterized/multiline
scripts and no-macro fallbacks retain their existing behavior. No printer macros
are edited, and no new automatic homing is added to unprefixed requests.

Validation: AddressSanitizer/UndefinedBehaviorSanitizer resolver tests reproduce
the dropped prerequisite on the preceding source and pass with the fix. Alias
coverage includes screws, Z tilt, quad gantry, bed mesh, probe and shaper actions.
The real LVGL geometry dialogs also run through the production resolver for
screws/Z tilt/QGL, with homed and unhomed cases. Hardware motion and ESP-IDF build
verification remain local.
