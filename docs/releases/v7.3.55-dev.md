# v7.3.55-dev — File request setup failure handling

Print start now checks Content-Type, API-key and body setter results before
acquiring the shared HTTP lane or performing the request. Failures clean up the
client, report HTTP zero and the exact setup error, and allow a subsequent retry.

The shared raw GET helper also rejects API-key header setup failure before
transmission. This covers file lists, metadata/status and thumbnail requests,
including the caller-owned exclusive download path. Captured length/status stay
zero and the response starts empty; exclusive ownership remains with its caller.

The request-boundary fixture now includes production Moonraker state/capture
types rather than an outdated local capture declaration. It exercises metadata
names of 255 bytes encoded to 765 bytes, while retaining the separate 159-byte
print-start filename boundary. The earlier test required a missing state type
and no longer compiled against the current metadata path sizing.

Validation: ASan/UBSan failure injection reproduces print-start transmission on
the previous code and passes with the fix. Tests cover all setup stages, metadata
output clearing, raw shared/exclusive ownership, anonymous print-body failure,
immediate retry, exact-limit filenames and oversized paths. Command, thumbnail,
security-boundary and demo-isolation suites also pass. ESP-IDF/tablet and real
network verification remain local.
