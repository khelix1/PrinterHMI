# v7.3.56-dev — Endpoint verification and live capture

Endpoint verification no longer accepts keyword matches in arbitrary or truncated
text. It requires a result object with a nonempty string klippy_state, rejects
error envelopes, and parses complete bounded JSON with the existing shared
json_document_parse_bounded helper (depth 16). A reusable 8192-byte heap buffer
replaces the 384-byte stack prefix; allocation uses PSRAM with an ordinary
8-bit fallback. Responses exceeding 8191 captured bytes are rejected.

Optional printer-info lookup preserves verified server readiness when unavailable,
but a valid later shutdown/error/disconnected state now clears ready rather than
leaving the earlier true value latched. JSON string decoding handles escaped
hostnames. Optional lookup failure still permits the verified Moonraker result.

Probe capture rejects truncation and embedded NUL bytes. Webcam-list parsing also
uses the shared bounded parser within its existing 4096-byte buffer. Endpoint,
webcam and live-poll requests abort if API-key header setup fails. Live captures
reject embedded NUL bytes as well as overflow, leaving reported response length
zero on failure.

Validation: new production probe/live transport fixture under ASan/UBSan covers
schema/identity/readiness, stale-ready regression, optional lookup failure,
large valid replies, malformed/trailing/deep/truncated/NUL responses, webcam
JSON, header/init/allocation/lane/HTTP failures, retry, port/TLS/key forwarding
and cleanup balance. Endpoint-worker, security-boundary and demo-isolation tests
also pass. No real sockets/HTTP are exercised by these tests; ESP-IDF and tablet
verification remain local.
