# v7.3.57-dev — Camera discovery URL and result isolation

Camera discovery now rejects absolute URLs that do not fit instead of silently
truncating them. Exact-limit URLs still round-trip. URI schemes other than the
supported HTTP/HTTPS forms are rejected rather than converted into paths on the
printer's HTTP proxy. A scheme-like sequence inside a relative URL's query
remains ordinary query content.

Each accepted webcam entry is assembled in a cleared temporary structure before
copying into the result array. Missing, invalid or overlong optional snapshots
remain empty instead of retaining prior result bytes. A relative snapshot that
exceeds its output buffer is cleared. Disabled or rejected entries cannot
contaminate the next accepted slot. Webcam error envelopes are rejected even if
they also contain a camera list.

Validation: production probe/live fixture under ASan/UBSan reproduces the old
camera-list behavior and passes with the fix. Tests cover exact/overlong absolute
URLs, relative snapshot overflow, unsupported schemes, valid query content,
disabled cameras, output reuse, capacity and error envelopes. Catalog storage,
discovery-worker and demo-isolation checks also pass. No catalog entries are
removed automatically; hardware camera/network and firmware build verification
remain local.
