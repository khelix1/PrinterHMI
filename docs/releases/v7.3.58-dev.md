# v7.3.58-dev — Backup credential lifetime and passphrase boundaries

A private settings_backup_sensitive.h helper belongs to the backup service and
clears temporary owned JSON string data before tree deletion, serialized backup
plaintext before JSON allocator release, and configuration snapshots before
return. Plain-file read buffers are cleared using their allocation size. Cleanup
covers export, preflight, restore success, rejected loads and failed apply/
rollback paths. Borrowed JSON strings/children and constant keys are preserved.
Live configuration and on-disk backup formats are not changed.

The passphrase form previously limited characters while copying into a 97-byte
buffer. A long UTF-8 restore entry could therefore be shortened before reaching
the worker. The form now checks byte length before copying, retains the entered
text on failure and displays the same 12-to-96-byte range used by the worker.

Validation: real JSON allocation/free spies reproduce unwiped credential copies
on the previous source and pass after the fix. Production export/preflight/
restore functions are tested under ASan/UBSan for failure, rollback and cleanup;
the actual worker is tested for delayed/immediate completion, failed creation,
retries, busy rejection, terminal status and passphrase clearing. Real LVGL
Network/backup dialogs cover oversized multibyte export/restore input across
existing themes/densities/text/viewports. Backup rotation and security-boundary
checks pass too.

The earlier intermittent OTA crash after encrypted backup was not reproduced.
This patch does not claim a root cause or a fix for that crash. Tests mock crypto,
storage and scheduling at the service boundaries; full ESP-IDF build, memory
pressure, encryption and tablet/OTA transition verification remain local.
