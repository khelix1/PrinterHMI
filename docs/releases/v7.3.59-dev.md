# v7.3.59-dev — OTA persistence, cancellation flags and catalog recovery

The remembered custom URL now changes only after NVS set/commit succeeds.
Failed saves leave the prior in-memory value intact; overlong URLs are rejected
rather than shortened, and unchanged values skip flash writes. Input is captured
before storage calls so an aliased argument remains stable. A failed URL save
does not cancel an already-started update. This does not promise atomic NVS
rollback if the storage device reports a failed commit.

OTA running/cancellation/completion flags now use C atomic objects rather than
volatile flags, providing defined cross-core access. Existing progress locking,
cancel cutoff before image validation, worker-owned SDK cleanup and UI completion
acknowledgment remain in place.

Release capture rejects embedded NUL bytes, preventing a valid prefix from
masking extra response data. GitHub Accept/API-version/User-Agent setup errors
clean up the client and temporary buffers before network acquisition or request
transmission. Failed requests retain the existing catalog and permit retry.

Validation: production OTA worker cases cover URL save failures/no-op/exact limit,
known/unknown image size, cancellation, transient/stalled reads, incomplete image,
SDK/task/lane failures and frozen progress. New production catalog worker checks
cover setup/NUL failures, retained catalog, balanced client/buffer/lane cleanup and
retry. Existing release parsing/channel, real LVGL OTA-failure and demo-isolation
checks pass. Actual firmware flashing, target multicore timing and tablet OTA
verification remain local. The historical OTA-after-backup crash is unconfirmed.
