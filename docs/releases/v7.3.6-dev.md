# v7.3.6-dev

Profile storage failure handling stays in the configuration controller. A failed configured-flag write now stops immediately instead of falling through to API-key deletion. Basic connection-field edits retain existing camera URLs and TLS choices.

Migration only runs when the profile schema key is absent. Unreadable or unsupported schemas return failure without writing; an existing collection with no loadable profiles is no longer overwritten by defaults. The existing runtime default remains available for setup on load failure.

An unreadable, mistyped or malformed TLS field requires secure transport rather than falling back to plaintext. A missing TLS field still supports older HTTP-only profiles. This protects detected read errors, not undetectable deletion of a legacy-optional field.

The actual controller passes NVS fault injection under AddressSanitizer and UndefinedBehaviorSanitizer. Tests also check RAM rollback, generation changes, camera preservation and legacy migration. Separate NVS writes are not a power-loss-atomic collection transaction. Security-boundary, demo-isolation and profile UI regressions are checked separately.

Build with `./tools/build_idf6_hosted3.sh`. On the tablet verify profile rename/save, camera retention, profile switching and reboot persistence; verify a configured TLS printer remains secure.
