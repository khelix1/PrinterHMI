# v7.3.60-dev — Group accessibility preference saves

Accessibility Save previously performed four separate open/set/commit operations.
If a later option failed, earlier options were already committed while the live
UI retained its old options. Reboot could therefore reveal a partial selection.

The theme manager now opens storage once, writes large text, high contrast,
reduced transparency and reduced motion, then commits once after all setters
succeed. Live options update only after commit success. Failure closes the handle
and permits retry. No preference schema or option defaults change.

Validation: ASan/UBSan regression tests reproduce earlier committed options on
the preceding source. The fixed function passes storage-open, each-key and
commit failures, mixed selections and retry; a successful save uses four sets
and one commit. Real theme manager/defaults and LVGL appearance-dialog tests pass.
The storage fixture stages writes until commit as specified by the API; this is
not a power-loss transaction or a guarantee of recovery from flash corruption.
ESP-IDF build and tablet persistence checks remain local.
