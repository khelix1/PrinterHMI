# v7.3.61-dev — Keep temperature actions tied to their dialog

The generic nozzle dialog sends M104, which targets the active tool. An external
tool change while that dialog remained open could heat a different nozzle than
the one whose values were displayed. Dispatch now compares the current active
hotend with the one captured at opening. A mismatch keeps the dialog open and
asks the operator to reopen it. Explicitly selected heater controls retain their
named target and remain usable when the active tool changes.

Preset dispatch also requires an enabled button belonging to the current control
popup and rejects events bubbled from child objects. Existing printer-session,
job and connection checks remain in the shared dispatch path.

Validation: real LVGL popup tests cover stale preset/custom nozzle commands,
reopening, named heaters, disabled/foreign/child events and ordinary fan commands,
plus the existing callback lifetime and layout cases. Adjacent hotend and lighting
checks pass. ESP-IDF build and tablet verification remain local. This checks state
at dispatch; it cannot make remote tool selection and M104 execution atomic.
