# v7.3.62-dev — Preserve parsing state during manual motion

Toolhead jog scripts previously ended with G90, even if the printer had been in
relative coordinate mode. Manual extrusion selected M83 and left that mode in
effect. Both changed the active feedrate. A later command could consequently
interpret coordinates, extrusion or speed differently.

Successful jog and extrusion scripts now save the parsing state under the
reserved name PRINTERHMI_TOOLHEAD and restore it with MOVE=0. This preserves
the prior modes, parsing offsets and speed without returning the toolhead to its
previous position. Home and intentional runtime Z-offset adjustments retain
their existing commands. Scripts use bounded temporary output; undersized caller
buffers are cleared and refused. The shared simulation accepts the exact wrapped
commands and rejects incomplete restores, extra commands and MOVE=1 variants.

The implementation uses Klipper's built-in
[SAVE_GCODE_STATE and RESTORE_GCODE_STATE](https://www.klipper3d.org/G-Codes.html#save_gcode_state).
No printer configuration changes are required. A Klipper command error can abort
a script before its restore line; this change does not provide error-finally
semantics or bypass motion/heater checks. PRINTERHMI_TOOLHEAD is reserved for
these commands; pause/default saved states are not overwritten.

Validation: the preceding formatters fail the new parsing-state regression. The
fixed scripts pass coordinate/extrusion-mode combinations, feedrate/override and
origin checks, logical E continuity, one intended move, short-buffer checks,
production demo parity and malformed-script rejection. Native LVGL Toolhead and
filament recovery lifecycle/layout checks pass, as do the recovery macro and
shared simulation suites. The parsing-state fixture models documented semantics;
it does not execute Klipper or its planner. ESP-IDF build and physical
jog/extrusion verification remain local.
