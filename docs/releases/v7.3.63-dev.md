# v7.3.63-dev — Keep probing out of the print-layer estimate

The old resolver inferred a layer from raw G-code Z whenever file progress was
positive, including while START_PRINT was heating or probing. For example, a
20 mm lift with 0.5 mm layers could display layer 40 before the first layer.

Absent/zero layer reports now stay at zero during preparation. Estimation starts
only after positive print duration and, when available, positive finite filament
usage. Explicit zero filament usage holds preparation at zero even if duration
has advanced. Older producers without filament-use telemetry use print duration
as a compatibility fallback. A positive layer reported by Klipper remains
authoritative. Dashboard and Printer use the same pure resolver policy. Existing
job changes already clear duration, filament evidence and previous layer reports.

This fixes premature layer 40 and probing oscillation before printing. It does
not turn raw-Z or percentage estimates into exact slicer layer counts: once
printing, Z hops and variable layer heights can still affect estimates when
Klipper does not report layers. Exact reports remain the preferred source.

Validation: ASan/UBSan regression checks fail on the preceding resolver and pass
with this fix. Tests cover raised/probing Z, nonzero/invalid file percentages,
missing and zero reports, zero/invalid filament data, positive Klipper reports,
active external-start estimates and older telemetry fallback. The real LVGL
Dashboard runtime exercises preparation, first extrusion, pause, offline and
reconnection behavior. ESP-IDF build and a physical START_PRINT sequence remain
local checks.
