# v7.3.64-dev — Use active-job layer metadata and first-layer thickness

Active-print layer dimensions were stored in the selected-thumbnail session.
The resolver ignored metadata layer_count and first_layer_height and always
used object_height / layer_height. That could give wrong totals and count a
thicker first layer as multiple layers.

The existing active-file background metadata worker now carries validated layer
count, first-layer height, normal-layer height and object height. Its cache is
already keyed by file, job revision and printer generation. Both page paths use
that data; Dashboard additionally fences the context against its fresh job and
profile snapshot. No extra worker or G-code download is introduced. The old
thumbnail-owned layer cache and exported getter are removed.

Reported Klipper counts remain first priority. Metadata layer_count is used next
when available. Height-derived estimates account for first-layer thickness and
round up a partial final layer. For example, a 0.4 mm first layer with 0.2 mm
later layers gives layer 2 at Z=0.6; a constant-layer 10 mm model has 49 layers.
The preparation gate from v7.3.63-dev remains in effect.

Moonraker documents first_layer_height in its
[file metadata API](https://moonraker.readthedocs.io/en/latest/external_api/file_manager/#get-gcode-metadata);
its [metadata extractor](https://github.com/Arksine/moonraker/blob/master/moonraker/components/file_manager/metadata.py)
also supports layer_count for supported slicers. Missing counts retain the
height fallback. These changes improve estimates but do not make live-Z
fallbacks exact for Z hops, variable layers or sequential object printing.

Validation: production resolver regression fails against the preceding code
and passes the new first-layer/count/partial-layer and numeric-boundary cases.
Worker tests exercise count-only metadata, missing/invalid fields, the actual
main.c selection helper, failed fetches, retries and stale file/job/profile
results. Real Dashboard pipeline checks metadata count priority, first-layer
indexing and rejection of stale contexts; existing telemetry, print-estimate
and thumbnail request ownership checks pass. ESP-IDF build and tablet checks
remain local.
