# v7.3.65-dev — Preserve profiles and credentials after storage read failures

This batch resumes the general bug pass after v7.3.62-dev. Layer fixes through
v7.3.64-dev remain included.

The profile loader treated failed API-key and camera-URL reads as empty values,
and failed port reads as port 7125. A subsequent edit saved the complete
collection and could erase a stored credential or change the stored port. The
host regression reproduces the actual key erasure on preceding production code.

A genuinely missing legacy optional field is still compatible. Other read
errors, malformed string extents and invalid existing fields now mark the
collection incomplete. Ordinary profile saves, selection changes, deletion,
camera and TLS edits are refused before mutating runtime fields or storage.
A successful complete reload clears protection. Explicit validated full profile
replacement, used by backup restore, can recover the collection; failed
replacement preserves the protected state.

Unreadable schema, required active-profile data and active-selection errors no
longer publish a guessed default HTTP endpoint. Valid known profiles may remain
usable when another profile is unreadable. Unreadable/malformed TLS flags retain
secure-only behavior and prevent writeback. Fresh first-run creation and missing
legacy fields remain supported. The profile editor gives restart/retry or restore
guidance locally and retains the draft.

Wi-Fi loads also validate returned NVS string sizes, termination and supported
SSID/password byte limits. Invalid loads clear both caller buffers; a subsequent
valid read can retry normally. Open networks and full-width credentials remain
supported.

Plain and encrypted export refuse to create a new backup from an incomplete
profile load, preserving existing recovery files. Full backup restore remains
available. This is protection against read-failure writeback, not a transaction
across NVS keys: flash write failures and partially failed restores still require
the existing rollback/status handling and cannot guarantee recovery of an
already unreadable original collection.

Validation: ASan/UBSan profile and Wi-Fi fault injection, old-source key-erasure
and malformed-read regressions, first-run and legacy migration, full replacement
failure/recovery, fail-closed TLS tests, native LVGL profile layouts/retained draft
feedback, backup sensitive-data/worker checks and actual backup file promotion
and restore progress checks pass. SDK/physical storage and tablet validation
remain local.
