# v7.3.67-dev — Revalidate calibration selections

The PID selector previously accepted every object beginning with `extruder`,
including `extruder_stepper` motors. It now accepts the extruder heater names
(`extruder` and numeric suffixes), the bed and nonempty generic-heater names.

PID and custom-calibration dialogs retain their own reviewed names. Their source
catalogs can reset or rebuild during a same-printer reconnect, without changing
the active profile generation. Previously Run sent the old selection without
checking that it was still discovered. Both UI owners now require the reviewed
name in the current discovered catalog before creating a calibration session,
logging its command or dispatching it. Missing selections retain the confirmation
with guidance to close and select again. A reordered catalog still dispatches
the reviewed name; no selection is silently substituted.

This is a local catalog check, not a guarantee that the printer configuration
cannot change after dispatch. Existing readiness, print-state, owner-generation,
transport-retry and popup-lifecycle checks remain in place. PID filtering and
confirmation behavior stay in the PID UI owner; custom macro confirmation stays
in its own UI owner. No network or catalog persistence is added to either.

Validation: real LVGL PID and custom-dialog suites cover unavailable catalogs,
removed selections, reorder/retry, motor filtering, printer switches, failed
sends and popup retirement across themes, density and text-size variants.
The preceding sources fail the new unavailable-catalog dispatch assertions.
Separate calibration translation units compile with warnings treated as errors.
ESP-IDF build and tablet validation remain local.
