# v7.3.68-dev — Correct Console severity and calibration completion

Console previously searched entire response lines for severity keywords. A
normal informational line containing an error estimate, a failure counter or a
literal `!!` could therefore become an error and abort an active calibration.
Severity now uses leading markers/labels after optional whitespace and `//`.
Klipper's `!!` errors, explicit error/warning labels, unknown/invalid commands,
homing errors and the Shutdown state remain recognized. Ordinary embedded
keywords stay informational. Custom output requiring alert styling should use
an explicit leading severity label or the normal Klipper error marker.

Calibration previously treated warning text mentioning SAVE_CONFIG as successful
completion. It also accepted that text inside longer macro identifiers, and the
SAVE_CONFIG entry in a HELP listing could unlock Apply & Restart before any
calibration finished. Warnings now remain context without authorizing completion
or saving. SAVE_CONFIG evidence must be a separate command token, and its HELP
command-description line is ignored. Standard positive save guidance and the
local demo's successful result messages remain accepted. This is still a bounded
text interpretation of the active printer's Console output, not authenticated
proof that an unrelated message cannot imitate a result.

A successful TEST_RESONANCES produces a final CSV-written response, not a request
to save configuration. That final response now completes its session without
setting save_available. Previously its results stayed incomplete and eventually
became a timeout error. Partial output still times out normally. Probe accuracy,
accelerometer checks and screw results retain their own completion policies.

Severity stays in console_controller; result and persistence decisions stay in
calibration_session_controller. No UI, network, storage or command dispatch is
added to either responsibility.

Upstream response behavior was checked against Klipper's
[gcode formatter](https://github.com/Klipper3d/klipper/blob/master/klippy/gcode.py),
[configuration help](https://github.com/Klipper3d/klipper/blob/master/klippy/configfile.py)
and [resonance tester](https://github.com/Klipper3d/klipper/blob/master/klippy/extras/resonance_tester.py).

Validation: the real Console JSON-ingestion/calibration pipeline passes
ASan/UBSan fixtures for severity, HELP/identifier/warning save gates, successful
results, explicit errors and resonance completion/timeouts. Preceding Console
and session sources fail the new regressions. Console frame/filter/transport,
Tools gates/session ownership, real LVGL Console/results and demo-isolation
checks pass. ESP-IDF build and tablet verification remain local.
