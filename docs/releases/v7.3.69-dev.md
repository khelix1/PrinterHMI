# v7.3.69-dev — Retire stale Bed Mesh data and confirmations

Resetting the active printer runtime previously cleared telemetry without
clearing the shared bed-mesh cache. The next printer could therefore display
the preceding printer's surface and saved-profile list before its own mesh
arrived. The runtime reset now calls the bed-mesh controller's reset API under
the same telemetry-to-mesh lock order used by status merge. Published geometry,
statistics, active name and profile count retire together. Allocated value and
profile buffers remain reusable; repeated initialization no longer loses them.
An unsuccessful mutex initialization now prevents merge and snapshot publication.

Klipper uses `[[]]` to represent no active mesh. The parser previously rejected
that shape and retained the old surface. It now handles both `[]` and `[[]]`,
while preserving profile-list-only and profile-name-only partial updates.
An empty interpolation matrix may still fall back to a nonempty probed matrix.
Saved profiles remain available after a legitimate active-mesh clear.

Retained grid rows must be rectangular and retained cells must be representable
numbers. Missing/null/string/boolean cells and malformed matrix containers no
longer become zero-height samples or change cached metadata. Rejected updates
preserve the last valid view. The existing 33-by-33 display limit and truncation
behavior remain; validation covers the geometry retained for display.

An open Save confirmation becomes disabled when the current mesh disappears;
an open Remove confirmation becomes disabled when its reviewed name is no longer
reported. Both show local guidance and restore retry when availability returns.
The renderer clears an invalid surface even when saved profiles still make the
snapshot available, avoiding an old surface beneath an empty-mesh caption.

Cache lifetime/parsing remain in bed_mesh_controller, runtime reset remains in
moonraker, confirmation policy stays in ui_bed_mesh_profiles and canvas clearing
stays in ui_bed_mesh_renderer. No new network or persistence work enters the UI.

Klipper's empty-mesh representation was checked against its
[bed-mesh status implementation](https://github.com/Klipper3d/klipper/blob/master/klippy/extras/bed_mesh.py).

Validation: ASan/UBSan parser tests cover malformed and nonfinite cells, partial
updates, clear/fallback semantics, failed mutex creation and buffer reuse over
repeated reset/reinitialization. The real runtime-reset/JSON fixture now links
the actual mesh controller and verifies that printer A's geometry/list cannot
survive into printer B's runtime. Real LVGL profile/live-view and renderer tests
cover disabled stale reviews, exact retry scripts, saved-profile-only canvas
clearing, stride/canary bounds and the existing layouts/gestures. Preceding
implementations reproduce the clear/reset and UI regressions. Connection-control,
readiness, Tools-session and demo-isolation checks also pass. ESP-IDF build and
physical tablet checks remain local.
