# v7.3.7-dev

Camera catalog and persisted preview hardening in one batch.

Camera names and URLs that exceed entry capacity are rejected before writes, including before the primary camera URL can change. Exact-limit values still round-trip. Lookup clears output on invalid input, distinguishes missing slots from URL read failures, and rejects malformed stored URLs.

SD preview metadata requires complete bounded lines, a strict port in 1..65535, a nonempty filename and no trailing data. Preview persistence rejects filenames containing line breaks or exceeding the cache field capacity. This affects optional cached previews, not printer filenames or print commands.

Restore reads the shared image cache under the display lock, performs SD I/O outside it and rechecks generation/cache state before publication. An image published by the live worker during I/O wins. Profile changes discard the stale result, and busy display locks are retried on subsequent worker cycles. Allocated PNG data is released on every tested path.

The actual catalog, metadata readers and full preview-store module pass fault injection under AddressSanitizer and UndefinedBehaviorSanitizer. Released sources reproduce the oversized camera-save and unlocked cache-read regressions. UI camera/preview and demo-isolation regressions are checked separately.

Build with `./tools/build_idf6_hosted3.sh`. Verify camera edit/default/view/fullscreen behavior and preview restoration across reboot, SD-card availability and printer switching on hardware.
