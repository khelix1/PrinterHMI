# v7.3.70-dev — Harden shared JSON strings and lighting sessions

cJSON exposes parsed keys and values as C strings. An encoded null character
could previously make a longer JSON identifier compare as a shorter trusted
one. The shared bounded-JSON preflight now rejects encoded NUL characters in
string keys and values, before cJSON parsing. It already rejected literal NUL
bytes. Literal backslash-u text and ordinary nonzero Unicode escapes remain
valid. This policy applies to consumers using the shared preflight/parser,
including WebSocket status, Files, metadata, Console, OTA catalogs, probes,
custom themes and settings backups; it is not a claim about every JSON parser
in the project or every possible malicious input.

Lighting status envelopes containing an error field are now ignored, even if
that field is null or the envelope also contains plausible status data. They
cannot change the displayed live value or complete a pending light command.
Normal command-error responses retain their separate failure/retry path.

The lighting controller's session now advances when discovered availability
changes. If case_led disappears and returns within one UI refresh interval,
releasing a slider pressed before that transition cannot dispatch a command.
The existing UI session guard handles the change; no new UI command policy is
needed. Repeated unchanged discovery keeps a valid in-progress gesture intact.

JSON string validation stays in the shared parser preflight. Live-value,
availability and lighting-session ownership stay in case_lighting. The existing
UI still owns slider/toggle events and local feedback. No new network worker or
persistence path is introduced.

The broader check also exposed an outdated deep_failure_paths_test fixture:
it still referenced a removed local semantic-version helper and omitted the
current shared parser dependencies. It now tests the production firmware-version
parser and real JSON headers while retaining the original worker, theme-read,
catalog-lock/task and URL-boundary assertions.

Validation: ASan/UBSan boundary tests cover encoded NUL keys/values, backslash
parity, normal Unicode and exact-sized nonterminated input. Lighting model,
transport and lock tests cover malformed status and retained retries. Real LVGL
lighting tests cover disappear/return and unchanged-discovery gestures across
all theme/density/text variants. Preceding parser/model implementations fail the
new regressions. Existing Files, metadata, Console, OTA catalog/worker, probe,
backup, theme, security-boundary, deep-failure, connection-race and demo checks
pass. ESP-IDF build and tablet verification remain local.
