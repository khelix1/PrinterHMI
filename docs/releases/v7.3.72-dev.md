# v7.3.72-dev — Retire stale printer connection alerts

Connection cards previously survived deleting or editing their printer profile.
The background observer identified a profile using only host and port, so a
changed name, API key or TLS setting could inherit an old offline baseline and
emit a false recovery notification. It now compares the connection identity
(name, host, port, API key and TLS setting), retires that slot's obsolete
connection cards and establishes a new verified baseline. Inactive edits are
handled even when the active configuration generation does not change.

Deleting a profile also retires its connection cards. Other printers' cards and
unrelated print/fault notices remain queued, and recorded Event History is not
cleared. If retirement empties the queue, its old surface and overflow count
retire as well. Active and background transitions share this queue cleanup.
A same-slot active configuration-generation change also retires an old connection
action, even if the compared profile fields have not changed.

The observer privately retains only the fields needed to compare connection
identity. Those cached fields reset when the slot is removed or rebound; camera
URLs are neither copied nor used as connection identity. This adds no storage
or network work. Observer policy and current-card ownership remain in ui_toast;
operator_event_log continues to own recorded history, and printer_profile_health
continues to own background health verification.

Quiet still shows genuine connection loss, faults and paused-print warnings.
Recovery still retires its offline warning, records the transition in Event
History and remains silent in Quiet. Standard/Detailed keep recovery cards.
The existing active three-second debounce, initial-baseline fencing and
background-health freshness rules remain unchanged.

Validation: real LVGL notification tests exercise deletion and edits to each
identity field under all three notification levels, including unchanged active
generation, preserved unrelated faults, fresh baseline establishment, genuine
later loss/recovery and camera-only changes. Active edits and generation-only
changes cannot retain old connection actions. The preceding implementation fails
the stale-profile regression. Existing notification layouts/lifecycles, Event
History, health freshness, notification backup and demo-isolation checks pass.
The native helper builds and its notification preferences and Event History
workflows pass. ESP-IDF build and physical-tablet checks remain local.
