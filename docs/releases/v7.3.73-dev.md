# v7.3.73-dev — Recover saved print-estimate preferences

A failed NVS open or read previously marked print-estimate preferences as loaded
before storage had been read. This kept the default progress, remaining-time and
ETA choices in use until reboot, even if the next read would have succeeded.

The preferences owner now returns defaults for that failed call and retries on
the next request. A genuinely missing namespace or key settles to defaults so
normal first-use behavior does not repeatedly access storage. Successful saves
update the cached choice; failed saves retain the previous choice. Demo settings
remain in RAM and do not read or overwrite the live selection.

The change stays in print_estimate_preferences; calculation and rendering policy
remain in their existing owners. It adds no format migration or network work.

Validation: the host preference/calculation fixture passes under ASan/UBSan with
open failure followed by read failure and recovery, missing namespace/key,
failed commit, successful save and demo/live switching. The preceding owner
fails the retry regression. Metadata ownership, Dashboard/Printer telemetry
refresh, all five telemetry themes and demo-isolation checks pass. ESP-IDF build
and physical-tablet checks remain local.
