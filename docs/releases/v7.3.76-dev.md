# v7.3.76-dev — Enforce profile setter boundaries

The profile controller previously accepted a primary camera URL for an unused
printer slot. It appeared in RAM, but persistence omitted it because that slot
was not configured. The setter now requires a valid configured profile, matching
the transport-security setter.

Saving a printer name now rejects strings that do not fit the profile field,
rather than reporting success after truncation. NULL or empty names still use
the default, and the maximum 31-byte name remains supported.

Validation uses the real profile controller with ASan/UBSan: invalid requests
must leave storage calls, RAM and generation unchanged, and accepted name/camera
edits must survive reload. Existing profile UI and camera catalog checks remain.
These changes stay in the profile owner and require no storage migration.
