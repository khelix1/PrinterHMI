# v7.3.8-dev

Console and Macros bug/security batch.

Console notification scanning now respects the supplied byte length, supports nonterminated buffers and rejects oversized, deeply nested, embedded-NUL or trailing-data documents. The existing WebSocket assembler already appends a terminator; the fixed Console API no longer depends on that caller behavior. Host sanitizers reproduce an out-of-bounds read in the released API with a nonterminated buffer. This is not proof of a remote exploit through the normal assembler.

The macro controller checks favorite blob size and terminators before comparisons, retries storage read failures, and publishes a favorite change in RAM only after successful saving. The explicit desired-state setter replaces the ambiguous toggle return value. The UI reports failure locally and supports retry. Duplicate legacy favorites are removed together, and full-list/no-op cases are handled explicitly. Favorites remain panel-local shortcuts shared across printer profiles.

Overlong discovered macro names are omitted and flagged as truncated catalog coverage, rather than emitted as shorter commands. Parameter updates preserve nonzero catalog generations across wrap.

Production Console and macro code pass fault injection under AddressSanitizer and UndefinedBehaviorSanitizer. Released sources reproduce both nonterminated Console-frame and malformed-favorite-blob reads. Command dispatch, printer ownership, UI lifecycle, responsive Macros, calibration callers and demo isolation are checked separately. No firmware signing or transport policy changes are included.

Build with `./tools/build_idf6_hosted3.sh`. On hardware, check Console responses and Macros search, long-press Favorites add/remove, persistence after reboot, and switching printers with macro dialogs open.
