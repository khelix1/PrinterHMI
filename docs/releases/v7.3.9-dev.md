# v7.3.9-dev

Favorite long presses no longer open a macro run popup on release. Macro rows use `LV_EVENT_SHORT_CLICKED` for opening the run dialog, while long presses own Favorite changes. LVGL emits the ordinary click event after a long press; that event now has no run-dialog handler.

Favorite feedback remains on the Macros page and is written after row rebuilding so it is not immediately replaced by the macro count. Favorite callbacks also reject stale printer pages and actions behind an open macro dialog. Normal short taps still open the run dialog.

The command-surface fixture drives an actual LVGL pointer through press, hold and release for Favorite add and remove. It verifies no dialog or command is produced, inline feedback remains visible, and a subsequent short activation opens the run dialog. UI fixtures emit short-click events for macro rows consistently.

Build with `./tools/build_idf6_hosted3.sh`. On the tablet long-press to add and remove Favorites, release each press, and verify no popup appears. Short-tap a macro to verify its run dialog still opens.
