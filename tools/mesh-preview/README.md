# Standalone STL model preview experiment

First batch: v7.1.9-dev on feature/gcode-viewer-3d. PrusaSlicer needs no changes,
custom build, plugin or running service. The converter uses Python's standard
library and runs on the desktop. The tablet loads the prepared mesh from SD.
It does not parse G-code to reconstruct this model.

## First tablet check

1. Apply the firmware updater and build with `./tools/build_idf6_hosted3.sh`.
   OTA image: `build-idf6-hosted3/PrinterHMI.bin`.
2. With the tablet powered off, copy `tools/mesh-preview/demo.phm` to the SD
   card's `/PrinterHMI/meshes/demo.phm` (create these directories if needed).
3. Open Tools > 3D G-code Viewer > Mesh > demo.phm.
4. Orbit by dragging, pinch to zoom, use Top/Front/3D, Reset, Solid/Edges and
   Details. Close returns to the existing G-code view. Test repeated opens,
   interruption while drawing/loading, different themes and memory recovery.

The demo is a 6,144-triangle fluted ring with a central hole, 3,201 vertices,
and a 75,356-byte file. It is generated by this converter, not an external
model or PrusaSlicer asset. Regenerate with:

```bash
python3 tools/mesh-preview/convert_stl.py --demo /tmp/demo.phm
```

## Convert your own STL

```bash
python3 tools/mesh-preview/convert_stl.py ~/Downloads/model.stl
```

This writes `~/Downloads/model.phm`. Copy it into `/PrinterHMI/meshes/` on SD,
then choose it from Mesh. Binary and structured ASCII STL are supported;
coordinates are interpreted as millimetres. The source STL/G-code are unchanged.
Export the orientation/assembly you want to inspect; printer placement and
slicer transforms are not automatically transferred. A model is standalone,
not automatically associated with a selected G-code file or live print.
Supports, infill, rafts and generated print moves are not included unless they
were themselves exported as part of the input mesh.

The default budget is 20,000 display triangles. Compare a few budgets on a
real object before settling on a target:

```bash
python3 tools/mesh-preview/convert_stl.py model.stl model_small.phm --triangles 5000
python3 tools/mesh-preview/convert_stl.py model.stl model_detail.phm --triangles 40000
python3 tools/mesh-preview/convert_stl.py model.stl model_exact_budget.phm --triangles 100000 --no-simplify
```

`--no-simplify` rejects an oversized mesh rather than clustering it. All outputs
still use 16-bit quantized positions, remove degenerate/duplicate triangles and
compute crease-aware normals; this is a display approximation, not exact CAD
storage or a replacement printing mesh. `--force` explicitly replaces an existing
output. Input and output may not resolve to the same file.

Vertex clustering is an independently implemented, bounded grid approximation,
not PrusaSlicer's quadric simplifier. The converter searches for a grid that fits
its triangle and vertex budgets. It can remove small features, close holes or
change topology; it is not an error-bounded or topology-preserving decimator.
It reports grid size and coordinate spacing. A zero grid size means no grid
simplification was needed, not mathematically lossless geometry. Keep the source
and compare the result, especially around thin features. Use models reasonably
near the coordinate origin for float precision on the tablet.

## Format: PHM version 1

All fields are explicitly little-endian. Header size is 80 bytes; exact file
length is required, with no trailing bytes. This is PrinterHMI's experimental
format, not an existing PrusaSlicer format or STL replacement.

| Offset | Type | Meaning |
| --- | --- | --- |
| 0 | 8 bytes | `PHMESH1` followed by NUL |
| 8 | u32 | Version 1 |
| 12 | u32 | Header length 80 |
| 16 | u32 | Vertex count, 1..65,535 |
| 20 | u32 | Triangle count, 1..100,000 |
| 24 | u32 | Flags: 1, encoded vertex normals |
| 28 | u32 | Payload bytes: vertices × 12 + triangles × 6 |
| 32 | 3 × f32 | Minimum XYZ |
| 44 | 3 × f32 | Maximum XYZ |
| 56 | u32 | IEEE CRC-32 of payload |
| 60 | u32 | Source facet count, up to 2,000,000 |
| 64 | f32 | Clustering grid spacing in mm, zero if unused |
| 68 | u32 | IEEE CRC-32 of header with this field zeroed |
| 72 | 2 × u32 | Reserved, must be zero |

Payload first contains 12-byte vertices: 3 × u16 position and 3 × i16 normal.
Positions decode per axis as `minimum + q * (maximum-minimum)/65535`. Normals
encode the unit vector at scale 32,767 and are normalized after decoding; zero
vectors and -32,768 components are rejected. Triangle records are 3 × u16
indices. Indices, repeated/degenerate vertices, finite coordinate bounds, flags,
counts, lengths and checksums are validated before publishing the model.

Payload size is at most 1,386,420 bytes; the complete file is at most 1,386,500
bytes. Current render storage is about `40 × vertices + 6 × triangles` bytes
plus the model header. The 952×412 canvas and float depth buffer add about
2.24 MiB. The demo's model storage is about 161 KiB. The G-code view can retain
its main model underneath; selected-layer detail is retired when Mesh opens.
Allocation failures leave existing views usable and show a retry message.

## Rendering and lifecycle

Smooth vertex lighting, crease splits, orthographic projection, interpolated
shading and per-pixel depth testing produce the solid image. The first batch
uses a fixed gold material and two-sided faces; it has no textures, automatic
support coloring, CAD editing, 3MF loader or direct slicer integration.

Projection and triangle work run in bounded batches across UI ticks. Drag/pinch
uses at most 2,000 sampled wireframe triangles, then restores the full selected
mesh on release. Edges mode draws the entire selected mesh incrementally.
During rotation, fitting follows the projected bounding box. The previous
wire image remains while the next frame projects vertices. A new file clears
old geometry before adopting its filename. No per-frame allocation occurs.

The SD loader is read-only, single-flight and limited to safe flat `.phm` names
of up to 80 ASCII characters under its own directory. The chooser lists at most
32 files from at most 256 directory entries. Background reads have a 30-second
budget, cancellation checkpoints and request/profile fences. File errors never
replace an existing mesh or relabel it. Close, external popup deletion,
parent viewer dismissal and printer switching cancel/retire owned work. Modal
hit testing keeps pinch on the visible canvas. Bed Mesh input is unchanged.

## Host validation and measurement

```bash
python3 tools/audit/mesh_preview_test.py
python3 tools/audit/mesh_preview_loader_test.py
python3 tools/audit/gcode_viewer_ui_test.py --lvgl-dir PATH --lvgl-lib PATH_TO_ARCHIVE
cc -std=c11 -O2 -I main main/mesh_preview.c main/gcode_toolpath.c tools/mesh-preview/render.c -lm -o /tmp/mesh-render
/tmp/mesh-render tools/mesh-preview/demo.phm /tmp/mesh.ppm
```

Core/loader checks use ASan and UBSan, with explicit ownership counts. Native UI
checks use real LVGL pointer events across five themes. Tests include binary
STL headers beginning with `solid`, ASCII parsing, budget reduction, deterministic
demo bytes, input preservation, CRC/count/index/normal/NaN/truncation checks,
OOM/cancel/task/profile/display failures, incremental/full raster agreement,
hole preservation, clipping and guarded buffers. UI checks include chooser,
allocation retry, old-model identity on errors, gestures/modal guards, pinned
Details Close, parent entry/forwarding and repeated cleanup.

Host timings are not ESP32-P4 timings. Target build, real SD reads, interactive
frame time, visual fidelity and memory recovery need tablet verification. Serial
`mesh_view` logs report triangle count and raster chunk microseconds.
